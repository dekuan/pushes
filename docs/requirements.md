# 需求与技术评估

## 目标

减少个人多仓库 push 操作的成本。工具仅管理启动目录范围内仓库，提供持续刷新的终端列表、手动推送及全部改动的一键暂存与提交输入。参考截图仅作为布局参考。

## 第一版范围

1. 全局命令 `pushes`，提供本地安装脚本、发布后的 URL 安装入口及 zsh Tab 补全。
2. 标题 `Pushes for Git`，右侧逐秒系统时间与时区偏移；第二行显示扫描目录。
3. 当前目录属于仓库则列一项；否则启动时只发现一级子目录的仓库。F 仅手动 fetch 当前选中的仓库。
4. 五列：仓库、当前分支、未推送提交数、状态、说明。列表左侧预留两列，选中行以 ▶ 和整行加粗标识，保留状态文字颜色与终端背景，不反白；ASCII 模式用 >。仓库列优先分配宽度。
5. 使用紧凑文本符号：红色 ! 表示未提交改动，黄色 ↑ 表示领先上游，绿色 ✓ 表示干净且同步；另补无上游、空仓库、detached HEAD、落后、分叉和操作错误等状态，通过 Status 与 Details 区分。
6. 底部五行依次展示去重后的远端名称/URL、最后提交（哈希、时间、摘要）、历史提交数及最近成功 fetch 时间、上游、状态或错误说明；不重复展示本地路径。
7. 上下键选择；T 将当前选中仓库移到第一行并保持选中，其他仓库顺序不变；每次按 T 将完整顺序写入启动目录下的 .pushes JSON 文件，启动时恢复顺序，新仓库排在最后，已不存在的仓库忽略；没有按 T 不创建或重写配置文件；Enter push；B 打开分支列表，上下键选择、Enter 切换、Esc 取消；C 在底部输入消息，Enter 执行 git add . 并提交全部改动，Esc 取消；F 仅手动 fetch 当前选中的仓库，不影响其他仓库的刷新计划，不受提交数量或自动 fetch 开关限制；Q 退出。输入区明确提示会暂存全部改动并提交，遵守 .gitignore；Esc 取消不暂存，不自动 push，进行中显示 COMMITTING，失败保留输入。
8. 本地默认五秒刷新，检查期间保留仓库状态，不显示 CHECKING；仅在检测到未推送提交数大于零时自动 fetch，默认间隔三十秒。数量为零或未知时不自动 fetch，仅文件改动不触发。抓取期间显示 FETCHING。时钟独立逐秒更新。任务在后台运行，有超时，不自动 pull。远端单方面更新需通过 F 手动发现，或等待本地存在未推送提交后触发自动 fetch。

## 术语和必要修正

“commit 没有提交”在此应称为“已有 commit 没有 push”；未提交文件是另一个独立状态，可以同时存在。领先数量以已配置上游为基准，没有上游就无法可靠给出数量，不显示虚假的零。fetch 前只能依据本地缓存，不能声称与服务器实时一致。绿色对号表示与已知上游一致，并非服务器实时确认。

切分支会修改工作树，因此第一版拒绝在脏仓库中切换。普通 push 可以推送已有提交，即便有未提交改动。推送遵循 Git 原有配置；工具不猜测没有配置的远端。远端推送配置可能不同于上游，文档明确此区别。

## 技术选择

程序自身版本以 Pushes 仓库的 HEAD 可达提交数表示（rN），显示在标题并支持 --version。普通连续 commit 自动增加计数，无需特殊提交命令或 hook；安装时嵌入版本，运行时不读取用户其他项目的版本。URL 安装临时克隆 main 的完整历史，源码与版本来自同一检出；本地安装要求非浅克隆。重新安装后才更新已安装版本，未提交改动不增加版本数。

Push 失败后，对该仓库自动 fetch 一次并刷新状态，不受未推送数量或自动 fetch 开关限制；保留原始 push 错误及 fetch 结果，不自动重试 push、不 pull 或合并。此次 fetch 计入刷新间隔，避免立即再次自动抓取。

采用 Python 3.9+ 标准库 curses、subprocess、concurrent.futures。纯 shell 能实现简单菜单，但动态刷新、键盘、弹窗、字符宽度和后台任务会让实现复杂且脆弱。Go/Rust 可将来提供单文件二进制、免 Python 安装，但需要按系统和架构构建发布。当前 Python 方案便于自行修改、无第三方依赖。

macOS 优先，Linux 可用；Windows 原生支持留待后续。URL 安装脚本已准备，必须先发布代码才可从 GitHub 下载。本次不自动提交或推送开发中的项目代码。
